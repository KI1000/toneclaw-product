# 06 产品规划重审

> 记录时间：2026-10-03 19:09:58 CST  
> 状态：当前产品规划口径  
> 取代关系：本文件取代 `04-产品方案.md` 的 P0 方向；`04` 保留为历史决策记录，不再作为当前排期依据。  
> 架构依据：`05-业务架构闭环.md`

## 1. 结论

当前产品规划从旧的“多平台 SaaS + 助手陪跑”路线，重写为：

```text
ToneClaw 桌面产品
+ DSH 内嵌引擎
+ Temu 单平台卖家经营闭环
+ 货盘 / 选品 / 商品图 / Listing / 上架
+ 软件计费与 Token 计费
```

第一版不追求大而全的多平台 SaaS，而是先完成一个平台的可运营闭环：

```text
ToneClaw × Temu
```

第一版要验证的核心命题是：

> 一个一人 OPC 跨境卖家，能否用 ToneClaw 从货盘 / 选品走到 Temu 商品上架，并让订单、履约、AI 用量和软件授权进入可追踪状态。

## 2. 产品定位

### 2.1 用户可见产品

用户看到、安装、付费、日常使用的是 ToneClaw，不是 DSH。

ToneClaw 定位为：

```text
跨境电商卖家 AI 经营产品
```

第一版主要用户：

```text
一人 OPC 跨境卖家
+ 小团队卖家
+ 想通过 Temu 快速跑通选品和上架的卖家
```

### 2.2 DSH 的位置

DSH / DeepSeek Harness 是内嵌引擎，不作为用户可见产品身份。

它负责：

- Agent / Session；
- Tool Runtime；
- Workspace；
- Permission；
- Job / Schedule；
- Plugin Composition；
- 桌面运行时。

ToneClaw 在 DSH 之上构建产品能力、业务对象、UI 和计费。

### 2.3 第一平台

第一平台是 Temu。

Temu 不是 ERP，而是第一接入的 Marketplace。第一版通过 Temu 验证：

```text
货盘 / 选品
→ 商品资料准备
→ 商品图生成
→ Listing 生成
→ 上架 / 上架草稿
→ 商品状态
→ 订单 / 履约可见
→ AI 用量与软件计费
```

TikTok Shop、Amazon、Shopee、AliExpress 等平台后续复制。

## 3. 规划原则

### 3.1 一个平台 = 一个可运营闭环

平台接入不能只定义为 API 同步。接入一个平台，必须让卖家在该平台上的关键经营动作形成闭环。

### 3.2 先闭环，后扩张

第一版优先跑通 Temu，不追求同时支持多平台。

### 3.3 核心对象优先

功能必须落在统一业务对象上，而不是散落在页面和工具里。

核心对象包括：

- Store；
- Supplier；
- SourcingItem；
- Product；
- ProductVariant；
- Listing；
- ListingDraft；
- PublishJob；
- Order；
- Fulfillment；
- Settlement；
- CostProfit；
- UsageRecord；
- Subscription；
- Task / Audit。

### 3.4 人工环节不能变成系统黑洞

第一版允许人工确认，但人工动作也要进入系统状态。

例如：

- 商品是否待审核；
- Listing 是否待确认；
- 上架是否失败；
- 失败原因是什么；
- 下一步该谁处理。

### 3.5 高风险写操作必须可控

凡涉及平台写操作，例如发布、修改价格、修改库存、创建备货单，必须有：

- 前置校验；
- 人工确认；
- 执行记录；
- 状态回写；
- 失败原因；
- 审计日志。

## 4. 旧规划取舍

### 4.1 保留

| 旧规划内容 | 新规划处理 |
| --- | --- |
| 卖家经营闭环思想 | 保留，并升级为统一业务模型 |
| 平台适配层 | 保留，但第一平台改为 Temu |
| 写操作三态机 | 保留，用于风险控制 |
| 审计留痕 | 保留，成为 P0 基础能力 |
| 选品数据源重要 | 保留，并升级为货盘 / 选品闭环 |
| 回流线思想 | 保留，但 P0 先做基础回流 |
| 账号安全和合规 | 保留 |

### 4.2 调整

| 旧规划 | 新规划 |
| --- | --- |
| Amazon / TikTok 是 P0 | Temu 是 P0 |
| Temu 是 P2 | Temu 提前为第一平台 |
| WIMOOR 是 ERP 引擎 | ERP 后续接入 |
| 多租户 SaaS 优先 | 先做桌面 / 单租户 / 单卖家闭环 |
| Python / FastAPI / Vue3 / PG 作为主线 | 以 ToneClaw 产品层 + DSH 引擎为主 |
| 16 项卖家活动全面覆盖 | 先聚焦 Temu 可运营闭环 |
| 工具订阅后置 | 软件计费与 Token 计费进入 P0 |
| 飞书作为重要通道 | 飞书只是可选通知 / 远程控制渠道 |

### 4.3 废弃或延后

以下内容不进入第一版核心：

- 多平台同时接入；
- 复杂广告护栏；
- 复杂客服系统；
- 多店矩阵；
- 企业版；
- 独立站；
- 复杂 ERP 深功能；
- 复杂 WMS；
- 复杂财务系统；
- 全自动无审核上架；
- 无平台官方能力支撑的爬虫或灰产方案。

## 5. P0 范围

### 5.1 P0 目标

P0 目标不是覆盖所有卖家活动，而是完成一条可用链路：

```text
店铺接入
→ 货盘 / 选品
→ 商品准备
→ 商品图生成
→ Listing 生成
→ 上架 / 上架草稿
→ 状态追踪
→ 订单 / 履约可见
→ 软件计费
→ Token 计费
```

P0 的完成标准不是“功能做完了”，而是：

> 一个卖家可以完成从候选商品到 Temu 上架状态可见的最小闭环，并且 AI 用量、软件权限和关键操作都有记录。

## 6. P0 模块

### 6.1 店铺接入

目标：让 ToneClaw 知道卖家是谁、店铺是什么模式、连接是否健康。

功能：

- Temu 授权接入；
- 店铺基础信息；
- 店铺经营模式；
- 授权状态；
- API 能力状态；
- 同步状态；
- 连接异常提醒；
- Token / Secret 安全存储。

P0 不做：

- 多店铺矩阵；
- 多平台店铺；
- 团队权限；
- 企业组织结构。

### 6.2 货盘

目标：提供卖家可选择的商品来源。

功能：

- 供应商 / 货盘数据导入；
- 候选商品池；
- 商品基础信息；
- SKU / 规格；
- 采购价；
- 建议售价；
- 起订量；
- 供货能力；
- 图片；
- 类目候选；
- 资质信息；
- 货盘状态；
- 商品来源追踪。

货盘不只是一个表格，必须能进入选品和 Listing 流程。

### 6.3 选品工作台

目标：把货盘候选商品变成可运营商品。

功能：

- 候选商品筛选；
- 平台 / 类目 / 价格区间过滤；
- 竞争度参考；
- 利润空间估算；
- 人工标记：候选 / 通过 / 拒绝 / 观察；
- 选品理由；
- 选品转商品；
- 选品历史。

P0 可以先做规则 + 人工确认，不追求全自动选品。

### 6.4 商品图工作台

目标：为商品生成可上架或接近可上架的图片。

功能：

- 主图生成；
- 细节图生成；
- 场景图生成；
- 图片改写；
- 多尺寸输出；
- 图片质量检查；
- 图片合规提醒；
- 图片版本管理；
- 图片与 SKU 关联。

所有生成动作必须记录 Token 用量。

### 6.5 Listing 工作台

目标：把商品转换成 Temu 可理解、可审核的商品资料。

功能：

- 标题生成；
- 卖点生成；
- 描述生成；
- 类目建议；
- 属性建议；
- 关键词建议；
- 价格建议；
- 库存建议；
- 合规校验；
- Listing 草稿；
- Listing 版本；
- 人工确认。

AI 生成结果只是草稿，最终提交前必须支持人工确认。

### 6.6 上架中心

目标：让卖家知道商品现在处于什么状态、下一步该做什么。

功能：

- Listing 草稿管理；
- 上架任务队列；
- 发布前置校验；
- 平台限制提示；
- 人工确认；
- 上架执行；
- 上架结果回写；
- 审核状态；
- 失败原因；
- 重试；
- 操作审计。

如果 Temu 官方 API 不支持某个写操作，第一版不能伪装成自动完成，而应降级为：

```text
导出 / 复制 / 人工操作 / 结果导入 / 状态确认
```

### 6.7 订单与履约视图

目标：P0 至少让卖家看到订单和履约的基本状态。

功能：

- 订单同步；
- 备货单同步；
- 发货单同步；
- 履约状态；
- 异常状态；
- 基础筛选；
- 待处理事项。

P0 不建议自动发货、自动创建备货单或自动改库存。

### 6.8 结算与利润基础

目标：让订单和商品成本开始关联。

P0 只做基础能力：

- 采购成本；
- 物流成本；
- 平台费用；
- 佣金；
- 汇率；
- 订单收入；
- 基础利润估算。

复杂财务、多币种对账、退款细算、税务处理可以延后。

### 6.9 软件计费

目标：让 ToneClaw 具备产品化收费基础。

功能：

- 订阅 / 授权状态；
- 套餐定义；
- 功能边界；
- 有效期；
- 坐席或设备数；
- 授权校验；
- 过期降级；
- 订阅变更记录。

第一版可以先做本地授权校验 + 后台校验，不追求完整电商计费后台。

### 6.10 Token 计费

目标：让每一次 AI 消耗可追踪、可配额、可结算。

功能：

- UsageRecord；
- 模型名称；
- 输入 Token；
- 输出 Token；
- 调用场景；
- 会话 / Workspace；
- 用户 / 设备；
- 成本估算；
- 配额；
- 套餐额度；
- 超额策略；
- 用量日报。

所有 AI 生成动作，包括选品建议、商品图、Listing、经营摘要，都必须产生 UsageRecord。

### 6.11 经营日报与提醒

目标：让卖家不是只看数据，而是知道下一步做什么。

P0 只做基础版本：

- 商品上架漏斗；
- 上架失败原因；
- 待处理事项；
- 订单异常；
- 履约异常；
- AI 用量摘要；
- 基础利润摘要；
- 飞书通知可选。

## 7. Temu 接入方式

### 7.1 前置确认

进入开发前必须确认：

1. Temu 卖家模式；
2. Temu Partner Platform 资质；
3. App Key / App Secret；
4. 授权回调；
5. 可申请 API scope；
6. 商品、类目、订单、履约、仓库相关 API 能力；
7. 写操作权限；
8. 频率限制；
9. 数据安全与合规要求。

### 7.2 推荐第一模式

如果卖家模式可选，第一版优先考虑：

```text
Temu 半托管
```

原因：

- 卖家承担更多商品、库存、订单、履约责任；
- 业务对象更接近完整卖家经营闭环；
- 更适合验证 ToneClaw 的商品上架和履约追踪能力。

如果目标用户主要是全托管模式，则 P0 必须调整：

```text
货盘 / 选品
→ 供货商品
→ 备货
→ 供货单
→ 结算
→ 利润
```

而不是强调传统意义上的完整 Listing 和订单履约。

### 7.3 官方 API 优先

只使用 Temu 官方开放能力和卖家授权。

不做：

- 爬虫；
- 逆向；
- 账号模拟；
- 绕过频率限制；
- 未授权写操作；
- 灰产方案。

如果官方能力不足，必须显式降级：

```text
自动能力不足
→ 系统生成草稿 / 导出资料
→ 卖家人工在平台操作
→ 系统导入结果
→ 状态回写
→ 审计留痕
```

## 8. 关键状态流

### 8.1 货盘到商品

```text
SourcingItem
→ Candidate
→ Approved
→ ProductCreated
→ ContentReady
→ ReadyForListing
```

### 8.2 Listing 到上架

```text
ListingDraft
→ Validating
→ WaitingApproval
→ Approved
→ Publishing
→ Submitted
→ PlatformReview
→ Live
```

失败路径：

```text
ValidationFailed
PublishFailed
PlatformRejected
NeedsManualAction
```

### 8.3 订单到履约

```text
OrderCreated
→ WaitingFulfillment
→ StockingRequired
→ Shipped
→ Delivered
→ SettlementReady
```

异常路径：

```text
SyncFailed
FulfillmentDelayed
DeliveryException
AfterSaleOpened
RefundRequested
```

### 8.4 AI 用量

每次 AI 动作都要生成：

```text
UsageRecord
→ Scene
→ Model
→ InputTokens
→ OutputTokens
→ CostEstimate
→ QuotaStatus
→ AuditLog
```

## 9. 里程碑

### M0：产品与模型冻结

目标：确认 P0 边界，冻结统一对象模型。

交付：

- 业务架构确认；
- Temu 模式确认；
- 货盘来源确认；
- P0 模块清单确认；
- 核心对象和状态机定义；
- 软件计费 / Token 计费策略草案。

完成标准：

> 开发不再根据模糊想象实现功能，而是按对象、状态和验收标准实现。

### M1：基础产品身份与店铺接入

目标：先把产品底座和 Temu 店铺连接跑通。

交付：

- ToneClaw 桌面产品身份；
- DSH 引擎集成；
- Temu 授权；
- 店铺信息；
- 连接健康；
- 基础安全存储；
- 基础审计。

完成标准：

> 打开 ToneClaw，可以连接一个 Temu 店铺，并看到授权和同步状态。

### M2：货盘与选品

目标：让候选商品能进入系统。

交付：

- 货盘导入；
- 商品池；
- SKU / 价格 / 图片 / 供应商信息；
- 选品筛选；
- 人工标记；
- 商品创建。

完成标准：

> 可以从货盘中选择若干商品，并创建为 ToneClaw 商品。

### M3：商品图与 Listing

目标：让商品具备可上架资料。

交付：

- 商品图生成；
- 标题 / 卖点 / 描述生成；
- 类目和属性建议；
- Listing 草稿；
- 人工确认；
- Token 用量记录。

完成标准：

> 可以从商品生成一组商品图和 Listing 草稿，并确认进入上架准备状态。

### M4：上架与状态回写

目标：让商品进入 Temu 或形成可执行上架任务。

交付：

- 上架前置校验；
- 上架队列；
- 人工确认；
- 发布执行或人工操作降级；
- 平台审核状态；
- 失败原因；
- 操作审计。

完成标准：

> 商品能形成上架结果或明确的人工处理任务，状态不丢失。

### M5：订单、计费与日报

目标：让闭环具备经营和商业化基础。

交付：

- 订单 / 履约同步；
- 基础异常提醒；
- 软件授权；
- 套餐边界；
- Token 用量；
- 配额；
- 基础日报。

完成标准：

> 卖家可以看到商品、订单、异常、AI 用量和基础利润摘要；系统能判断当前套餐和剩余额度。

## 10. P0 验收标准

P0 验收时，以下链路必须可用：

```text
连接 Temu 店铺
→ 导入 / 选择货盘商品
→ 生成商品图
→ 生成 Listing
→ 人工确认
→ 上架或生成明确上架任务
→ 状态可见
→ AI 用量可见
→ 软件授权生效
→ 基础订单 / 履约状态可见
```

必须满足：

1. 用户看到的是 ToneClaw，不是 DSH；
2. 店铺授权信息安全存储；
3. 关键写操作有确认和审计；
4. AI 生成都产生 UsageRecord；
5. 软件套餐能限制功能；
6. Token 用量能影响配额；
7. 失败任务有原因和下一步；
8. 官方 API 不支持的能力不能伪装成自动完成；
9. 卖家不需要理解 DSH 内部概念；
10. 单人 OPC 卖家可以在一个桌面端内完成主要操作。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Temu 模式未确认 | 闭环对象可能设计错误 | M0 冻结模式，优先半托管；如全托管则调整对象流 |
| Temu API 能力不足 | 上架无法全自动 | 使用草稿 / 导出 / 人工确认 / 结果回写降级方案 |
| 货盘数据质量差 | 选品和 Listing 不可用 | 定义货盘最小字段和质量校验 |
| 商品图质量不稳定 | 平台审核失败或转化差 | 图片版本管理 + 合规检查 + 人工确认 |
| Listing 生成不符合平台规则 | 上架失败 | 平台规则校验 + 失败原因回写 |
| Token 成本失控 | 毛利被 AI 成本吃掉 | UsageRecord + 配额 + 套餐 + 高消耗动作确认 |
| 软件计费过早复杂化 | 拖慢 P0 | 先做授权、套餐、额度、用量，不做完整财务后台 |
| DSH 被用户感知为产品 | 产品身份混乱 | UI、安装包、文案、日志全部 ToneClaw 化 |
| 多平台过早扩张 | 闭环做不深 | P0 只做 Temu |
| ERP 过早接入 | 工程量失控 | ERP 延后，P0 只保留成本 / 库存 / 履约基础对象 |

## 12. 待确认项

| 问题 | 影响 | 建议默认值 |
| --- | --- | --- |
| Temu 第一版接入半托管还是全托管？ | 决定商品、订单、履约对象 | 半托管 |
| 货盘来自哪里？ | 决定数据模型和导入方式 | 先做结构化导入，再做供应商数据源 |
| 第一版是否要求真实上架？ | 决定是否依赖 Temu 写权限 | 尽量真实上架；不支持则草稿 / 人工降级 |
| 软件计费先做订阅还是授权？ | 决定商业化链路 | 先做订阅 / 授权，不做完整财务后台 |
| Token 计费是预付费还是套餐额度？ | 决定配额和超额逻辑 | 先做套餐额度 + 超额限制 |
| 是否需要多店铺？ | 影响数据隔离和 UI | P0 单店铺 |
| 是否需要移动端？ | 影响通道和 UI | P0 不做，飞书只做通知 / 简单控制 |
